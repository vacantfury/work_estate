# Communication craft — the deliberate-improvement lane

*Communication as a trained career capability (design principle 16): written status, docs, code-review comments, meeting speech, presentations — and language polish where the writer wants it (first-class for a non-native-English writer: polish is part of the craft). The lane improves the user's OWN communication from their real artifacts; it never fabricates a voice that isn't theirs.*

## The mechanism — harvest, coach, log

1. **Harvest.** The lane's raw material already accumulates: the worklog, the rendered public view, docs and readouts, review threads, meeting notes. No new capture ceremony.
2. **Coach.** A periodic pass over recent artifacts returns concrete coaching: rewrites shown side-by-side (the writer's version → the stronger version, with the one-line why), recurring patterns named (hedging, buried leads, missing audience calibration, grammar habits), and ONE current focus area at a time — never a list of ten faults.
3. **Log — `local/state/communication.md`.** The focus-area history, the recurring patterns with before/after examples, and what has measurably improved. Candid and complete (standing record posture); this file is coaching state, read by the next coaching pass so progress compounds.

## Standing jobs (registry entries, `work-engine.md`)

- **Periodic coach** — the harvest+coach pass above, on a weekly-ish cadence; output to the log; escalates nothing (the user reads the log when they work on the focus area).
- **Pre-flight assist** — on ask, before an artifact that matters ships (a readout, a broad doc, a sensitive thread reply): a review pass for clarity, audience fit, tone, and language — suggestions only; the user's voice and the final text stay theirs.
- **Meeting/presentation prep** — for a stage event (`dev-workflow.md`), the narrative skeleton and anticipated questions drafted from the project record; delivery practice notes if asked.

## Rules of the lane

1. **Team idiom is the target register** (design principle 10) — coaching calibrates toward how THIS team actually writes and presents, discovered from its artifacts, not toward a generic style guide.
2. **The bar is effectiveness, not polish** (principle 7): coaching optimizes for the reader getting it in one pass, not for elegance; over-polish beyond the team's bar is itself flagged.
3. **The writer's voice survives.** Coaching sharpens what they mean; it never substitutes a model's phrasing habits for theirs. A rewrite the writer wouldn't say out loud is a bad rewrite.
