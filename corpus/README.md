# corpus/ — the genome

The generic convention modules the unfold (`UNFOLD.md`) selects from and adapts. Everything here is permanently employer-generic: portable working discipline only, written to stand alone, with zero personal data, zero references to private infrastructure, and no pre-specialization to any employer. The unfold never edits these files — it reads them as GENOMES and founds the work-side estate from them (design principle 19). Module references to `local/state/<file>` resolve to the owning estate project's state home via the hub's estate registry.

Modules:

- `task-convention.md` — the ordered-TODO task system: one home per item, states, annotations, archive discipline.
- `session-discipline.md` — how a working session stays reliable and cumulative: request typing, verification, capture-at-settle, form selection, the three-tier attention structure, the wrap protocol.
- `engineering-standards.md` — code defaults: Python tooling, parameters-in-config, mature-tools-first, tiered testing, version control, secrets hygiene, authority gating for agentic systems.
- `portable-skills.md` — the shortlist of recurring procedures worth materializing work-side as skills / instructions / checklists, each with a compact tooling-agnostic procedure sketch.
- `role-playbook.md` — applied-science working conventions for LLM product features (eval-driven development loops, eval/judge/experiment discipline, sustainable-pace calibration, working-in-the-org practice), distilled from public practitioner canon; provisional until confirmed against the team's actual practice (axis 2 of the build model).
- `agent-reliability.md` — literature-grounded conventions for building/evaluating agentic LLM features: the verification ladder (real checkers first, honest verified-vs-judged labels), structural-vs-heuristic controls, trajectory-level failure thinking, irreversibility classes + human-before-irreversible, eval/benchmark skepticism, and the rich-budget operating defaults (independent verify pass by default, cross-family monitors, adversarial ship stage, pass^k reliability claims); every point cited to peer-reviewed sources with evidence tiers; provisional until confirmed against the team's actual practice.
- `human-agent-collaboration.md` — designing the human's place in agentic workflows, as working discipline and as product vocabulary: typed human roles (spec-setter / taste judge / ground-truth source / authority gate), the empirical automation boundary, standardized choice surfaces (options + recommendation + do-nothing consequence + named default), interface investment rules (automate upstream first, richness only on judgment-bearing residue), and durable harvest of human corrections as calibration data.
- `project-lifecycle.md` — the whole-arc project workflow: continuous sourcing pipeline, per-candidate intelligence (docs, artifacts, asking people), decision criteria, communication/negotiation doctrine (refusal via prioritization, chasing before staffing), the initiative/PoC lane, execution and sync cadence, landing at a declared end; runs on the work-local portfolio board `local/state/projects.md`.
- `dev-workflow.md` — the staged development funnel inside an accepted project: whole-product design pass, substructure design naming the consequential decision points, choice tournaments (small time-boxed pre-experiments that eliminate the clearly-bad cheaply; survivors advance; the team incumbent always a candidate), a few comparable product variants where surviving choices genuinely differ, and the environment ladder (local test → shared test environment → production for the surviving one or two, monitored at every rung) to a declared completion; proportionality scales the whole funnel to the cost of being wrong; progress reports and presentations are stage events riding the team's ceremonies; one running project record per active project (team convention first, else `local/state/projects/<name>.md`).
- `risk-register.md` — the predictive half of failure management: a work-local register of anticipated failure modes (`local/state/risks.md` — mode · early-warning signal · coarse likelihood/impact bands · pre-planned reaction · escalation trigger), born from premortems (per project at accept, per transition — a first-90-days ramp seed included), reaction plans written calm with early honesty as the near-universal component, and calibration (predicted-vs-unpredicted checked at every real failure) keeping prediction honest instead of ceremonial.
- `company-watch.md` — standing company-wide intelligence: leadership and high-level people (what they formally lead, visibly push, casually signal), personnel events (promotions, departures, layoffs, reorgs — and why), and the direction it adds up to; the own org watched most closely, but proximity weights attention, never draws the boundary. One append-only signal log + four registers (`local/state/company.md`): leaders with trajectory, events, themes with lifecycle states, and the reward map (what the company actually rewards and penalizes); the evidence ladder grading signals by durability (resourcing > repetition > planning artifacts > reward evidence > rhetoric); the re-aim ladder (reframe → reshape → re-bet → pre-position) feeding the project pipeline's alignment criterion; the record candid and complete, kept for the user's benefit.
- `boundary-protocol.md` — boundary discipline, what belongs where: the self-contained premise (graded by benefit per design principle 17, with a three-line hard core), the record grain rule (every record the user keeps here is meaning-grain, employer-safe by construction), the division of subject matter, and the seed-refresh + credential rules.
- `research-infrastructure.md` — the substrate for research from the work machine: two stacks chosen by CONTENT (work stack — employer endpoints, secret store, compute — for anything employer-confidential; the user's own stack — their secret manager, LLM seam, private-engine clones, their own clusters — for their own research), the never-cross rule (employer-confidential never through the user's own channels), revocable per-device setup order, and the sync model (private engines in the user's own estate, public repos as rendered interfaces, the work machine a git CLIENT; push feasibility an intake §18 fact with a read-only-satellite fallback).
- `device-return.md` — the uninstaller pairing the graded boundary: the footprint register `local/state/footprint.md` (every personal landing logged at entry with its revocation path known), triggers (offboarding, reimage, repair, loss), and the exit procedure — issuer-side revocation first, local deletion second, employer content handed back through the employer's process, the user's closure note last.
- `health-guard.md` — the health floors and the work/personal wall: health above work, always; hard floors (sleep, real meals, the hard daily stop, movement/eyes, symptoms-outrank-commitments) delivered as execute-ready moment instructions; facility-docs-first-or-ask grounding; the work-machine tracker `local/state/health.md` (daily line + breach log, candid and complete); session enforcement (a crossed floor is named at the moment, exception-or-drift logged); the wall isolating work from personal life, with the on-call carve-out.
- `work-record.md` — the running log of everything done, day by day: ONE private full-grain record on the work machine (`local/state/worklog.md`, candid and complete — activity across and around projects, deliberately not the project tracker; daily `site:` line = the presence ground truth, tallied against policy floor + team norm, design principle 20c) plus a manager/team-visible PUBLIC VIEW rendered one-way from it (team idiom, audience-written, never a second truth); the public view's home and cadence discovered at intake from the team's real status conventions (docs/artifacts first, then ask the manager and a teammate), staged at `local/state/worklog-public.md` until resolved; feeds the manager-alignment running record, the weekly debrief, and review-time impact evidence.
- `work-engine.md` — the composition module: every module above a LANE of one running work workflow; the user's typed residue (gate · taste · eyes · hands) vs the system's standing work; the agent-jobs layer — registry (`local/state/agent-jobs.yaml`), budget-ranked queue on the work account's sanctioned tooling and token budget, the platform hand-off (`autoflow.md` executes the registry — scheduling, cycles, runtime adaptation), and the binding rails (work surfaces only, prepare-only at the human edge, team norms, candid records, health floors outrank the engine).
- `research-workflow.md` — the research lane: the applied-scientist research arc (question → internal-first grounding → hypothesis + eval design → experiment loop via the dev funnel → honest verdict → readout as a stage event) with binding provenance discipline; the lane's standing jobs and candidate funnel live in `auto_research.md`.
- `people.md` — the working-relationship system (relationship-system grade since 2026-08-19, design principle 20b): deliberate investment in relationships at every level (distinct from company-watch by aim — investment IN, not intelligence ABOUT); one card per person (`local/state/people.md`: who, cares-about, interaction log, threads, relationship state + cadence, next move; machine reads separate from the user's judgments), thread/wait tracking with a due lane (owed replies, silences past cadence, lapsing 1:1s — the system notices, the user never tracks who they owe), relationship campaigns for deliberate pushes, prepared moves with the human contact permanently the user's; the lifelong relationship layer is the user's own affair beyond the job — the work register never syncs anywhere.
- `benefits.md` — everything the role is eligible for (design principle 20a): benefit elections, budgets, programs, quotas/access, run on acquire-at-eligibility with a hard-window due lane (`local/state/resources.md`); catalog discovered from the employer's portals, elections prepared execute-ready with the submit press always the user's; holdings and their financial meaning stay in the user's own estate.
- `career.md` — the review cycle and the promotion case (design principle 20a): a continuously-current review draft in the employer's own instrument's shape plus a standing promotion dossier against the next level's bar (`local/state/review.md` + `promotion.md`), both READS of the worklog, portfolio board, and reward map — evidence over narrative, the rubric as practiced over the rubric as written, never reconstructed from memory at cycle time.
- `estate-structure.md` — shared structural conventions across the estate (design principle 20d): the hub's merged attention view (pull on ask, user pins), the campaign form for mid-scale ending arcs, lazy-founded per-project lessons/handbook files, the estate failures log + periodic self-audit job, the data-shape rule for scored/typed registers, the placement map (every content kind one named home in a hub registry table, intake §21), and forecast lines (dated resolvable predictions on any register, resolved against the world, calibration read at self-audit) — the last two added 2026-08-20, principle 23.
- `store.md` — the estate's typed data + scoring service (design principle 25): schemas per entity kind, project-owned scoring configs executed uniformly, append-only + user-layer protection; the data-shape rule is its contract.
- `finder.md` — the retrieval bus (design principle 25): one query seam over the job's KNOWLEDGE surfaces + sanctioned web (A8 source roster); digs and standing watches ride it.
- `llm_utils.md` — the work-stack LLM provider seam: one seam between the estate's code and every sanctioned provider (incumbents sit behind it as providers — discover-before-build resolves adapter-vs-build at intake), mechanics only (routing, retries, structured output, the usage ledger), secrets from the employer's store, model-choice policy staying with consumers; founds at the first code consumer.
- `devices.md` — the compute and device client: registry of reachable work compute (single truth; granted-but-idle capability is named waste), submission adapters behind one dispatch seam, run state ("what's running where"), the work machine's own runbooks; placement policy stays with owning projects; founds at the first granted compute target.
- `autoflow.md` — the automation platform: the runtime executing the engine's job registry — scheduler, cycle runtime (attention batched at cycle boundaries, results reallocate budget), worker dispatch on the sanctioned tooling, run ledger, liveness checks; mechanics only, gates ride through unchanged; founds at the first sanctioned scheduled job.
- `auto_research.md` — the autonomous research engine: the research lane's standing jobs (literature + internal prior-art scouts, eval-landscape watch, experiment monitor, analysis/writing assists) and the candidate funnel (generate → vet → package decision-ready candidates); the funnel never founds a bet — the user and their manager are the gate.
- `deliberation.md` — the hub's council for decision-grade moments (design principle 22): three seats as disjoint GROUNDINGS, never personas — first-person (self-model, worklog, communication log, health), positioning (promotion dossier, company store, people register), delivery (portfolio board, commitments, manager expectations) — evidence-or-silence per seat, blind reads then synthesis with conflicts stated plainly, health floors binding before deliberation, advisory-only through the standard choice surface; decision records with the deciding project, estate-wide ones in the hub's decision log with an outcome column the self-audit reads.
- `self-model.md` — the work-grain profile the estate runs on (design principle 22): one hub state file (identity/title/role charter, targets, working style and habits, calibrations incl. the presence baseline, the user's standing rules verbatim), seeded at unfold, maintained by the debrief/retro harvest loop (machine-observed lines labeled, user judgment lines only on the user's word); work grain only — the spine of the council's first-person seat and of session personalization.
- `messages.md` — the daily operation of the job's communication channels (design principle 23): inbox/chat triage into three lanes (needs-the-user, merged into the attention view · prepare-and-present, drafts staged never sent · note-only, substance routed to its owning register), threads homed on the people cards with the connections due lane noticing waits, and consequential meetings entered prepared and left recorded; runs entirely on the employer's own mail/chat/calendar surfaces — convention, never transport machinery.
- `communication-craft.md` — communication as a trained capability: harvest the user's real artifacts → concrete coaching (side-by-side rewrites, one focus area at a time, language polish first-class) → the log `local/state/communication.md`; pre-flight assists and stage-event prep; team idiom as the target register, effectiveness over polish, the writer's voice always survives.
- `work-report.md` — the twice-weekly steering loop (settled 2026-08-14): a real-time time record (`local/state/timelog.md`, append-only stamps — focused hours, intervals, overtime delta computed never estimated), a Tue + Thu work-end report (last-range retro: time · brain · did · value · plan-vs-actual + next-range plan: planned time · brain budget · schedule · targets · intended value) distilled from the time record + work record at record grain, and the user's review: they read each report and return a verdict + plan amendments that become the next range's plan of record.
- `sidework.md` — the collection beside the main projects: one local folder gathering real copies of the declared parts of the user's side repos (the on-demand grab — copies new/changed, never deletes, reports what arrived) plus jot sections (people, ideas, notes); nothing scheduled, nothing synced.

Where the employer or team has an established practice — documented or not — the team practice wins; these modules fill the gaps and govern personal working discipline only. The real convention is discovered from docs, artifacts (code, merged PRs, review threads), and teammates, and conformed to by default (design principle 10).
